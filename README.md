# Case Study: AI-Powered Order Management & Automation via WhatsApp Business

## 1. The Challenge (Business Problem)
Companies managing sales and customer support via WhatsApp often face operational bottlenecks: slow response times outside business hours, repetitive tasks (like sending PDF catalogs or quotes), and lost order data due to a lack of centralization. The goal of this project was to design a scalable, low-cost virtual assistant to automate customer service, document delivery, and data synchronization, operating 24/7 without human intervention.

## 2. Tech Stack
* **Orchestrator:** Make (Integromat) / n8n (Workflow management and business logic).
* **Communication Channel:** Meta Graph API (WhatsApp Business Cloud API).
* **AI Engine:** OpenAI API (High-speed, low-cost LLMs optimized for micro-interactions).
* **Database / CRM:** Google Sheets API.

## 3. System Architecture & Webhook Logic
The system was built using an Event-Driven Architecture, separating production (critical static flows) and development (experimental AI integration) environments to ensure high availability.

### Execution Flow (Step-by-Step):
1. **Data Ingestion (Webhook):** The Meta Cloud API sends a JSON payload via a `POST` request to the webhook configured in the orchestrator (Make/n8n) whenever a user sends a message.
2. **Parsing & Routing:** The orchestrator receives the payload, extracts key variables (sender's `WaId`, message `Body`, `Timestamp`), and filters out irrelevant events (e.g., read receipts) to save operational costs.
3. **Natural Language Processing (AI):** The user's text is sent to the OpenAI API using a strictly defined System Prompt. This prompt shapes the bot's behavior, giving it the brand's persona and restricting it to answer only about the product catalog and order management, preventing AI hallucinations.
4. **Database Interaction (Google Sheets):**
   * **Read:** If the client asks for availability, the flow queries the spreadsheet in real-time to check inventory.
   * **Write:** If the client confirms an order, the orchestrator extracts the purchase intent and automatically logs the client's data, date, and order details into a new row in the spreadsheet.
5. **Action Execution (Delivery):** Based on the user's intent, the orchestrator makes a return `POST` request to the Meta API to:
   * Send a conversational text message generated by the AI.
   * Trigger the delivery of a media file (e.g., a PDF catalog stored in the cloud).

## 4. Cost Optimization & Scalability Strategy
To make the project business-viable, the following strategies were implemented:
* **Efficient Model Selection:** Use of low-cost, low-latency LLMs (approx. ~$0.00035 USD per interaction), ensuring near-instant responses that do not degrade the user experience.
* **Context Caching:** Optimization of token consumption by leveraging system prompt caching, reducing AI read costs by 90%.
* **Environment Isolation:** Deployment of a v1 flow (static PDF delivery and rule-based responses) as a fallback layer, and a v2 flow (AI integration) that is scalable and easily modifiable without downtime.

## 5. Impact & Results
* **Availability:** 24/7 automated support and order taking.
* **Operational Load Reduction:** 100% automation in sending quotes, catalogs (PDFs), and logging orders into the database (Google Sheets).
* **Scalability:** Pay-as-you-go infrastructure allowing the business to handle from 10 to 10,000 monthly interactions without architectural changes.
